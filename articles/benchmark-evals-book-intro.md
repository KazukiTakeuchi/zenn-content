## 誰向けか — 3類型と、類型ごとに刺さる章

読者を3類型に分ける。類型ごとに、刺さる章と得られる判断を対応させる。

**類型1：個人開発でエージェントプロダクトを作っている人**
刺さる章は第3章と第6章である。得られる判断は「自分のタスクの評価セットを何件、どういう配分で作るか」と「LLMジャッジの数字を、校正したうえでどこまで信じてよいか」である。付録Aの雛形と付録Bの校正シートが、そのまま作業の出発点になる。

**類型2：スタートアップや受託で「デモは動いたが出荷判断できない」場面にいるエンジニア**
刺さる章は第5章と第7章である。得られる判断は「出荷ゲートをどの数字で止めるか」である。単回成功率ではなくpass^kで信頼性を報告する方法と、回帰スイートをCIゲートにするしきい値の決め方が中心になる。

**類型3：評価を組織で回すテックリード、QA寄りのエンジニア**
刺さる章は第8章、第11章、第12章である。得られる判断は「評価基盤をどのツール構成で、月いくらの予算で回すか」と「評価運用が壊れる典型パターンをどう先回りするか」である。ツール選定は機能ではなく課金単位とデータの置き場で決める、という視点が第8章と付録Cの中核である。

向いていない人も明記する。モデルの研究そのものを追う人、ベンチマークで競うこと自体が目的の人、コピーして動くコードレシピ集を求める人には、この本は合わない。扱うのは設計と判断基準であり、コードは最小限である。理由は次節の実例を見れば分かる。

## 売りの3点 — 付録の道具、数値付き判断例、運用の失敗例

15パートを均等に紹介はしない。購入の判断材料になるのは次の3点だと考えている。

### 1. 付録一式は「読む表」ではなく作業に使う道具である

付録の内容は次のとおりである。付録Aには、評価ケース1件の雛形とルーブリック例を置いた。付録Bには、ジャッジ校正シートと運用チェックリストを置いた。付録Cには、ツール選定マトリクスと規模別の推奨構成を置いた。

実物感が伝わるよう、付録Bの校正シートの記録項目を抜粋する。

| 記録項目（抜粋） | 何を残すか |
|---|---|
| 校正セットの構成 | 件数、層別の内訳、人間ラベルの付け方 |
| 人間同士の一致 | 生の一致率とCohen's kappa |
| ジャッジとの一致 | 混同行列、感度、特異度 |
| 補正後の報告値 | 補正式による補正値と信頼区間 |
| 判定 | 可／不可と、不可の場合の修正内容と再校正結果 |

シートが1回分で使い捨てにならないよう、回次ごとの履歴を並べる形式も含めている。評価は1回作って終わる仕事ではないので、記録の形式まで含めて道具にする必要がある。

### 2. 判断基準には実例が付いている

方針だけを語る本にはしないよう、各章に数値付きの判断例を置いた。1つ抜粋する。第7章のCIゲートの例である。

回帰評価（regression eval）は、すでに解けるようになったタスクの集合である。評価では絶対値ではなく、mainブランチとの差分を見る。たとえば5ポイントを超える後退があった場合に、マージを止める形を取る。ただし「5ポイント」という数値自体に普遍的な正解はない。しきい値は次の手順で導出する。同一コードのまま評価を繰り返し実行し、揺れ（成功率の標準偏差）を実測する。PR側と基準値の差の95%範囲に、マージンを足す。第7章では50件×3 trial・同一コード10回実行の実測例で、この手順を一本通している。

逆に、まだ解けないタスクの集合であるcapability evalはゲートに使わない。解けないタスクでマージを止めれば、開発者はタスクを外すか基準を緩めるかしてゲートを通そうとし、測るべき能力の定義自体が歪むからである。

ツール選定でも同じ形式を取っている。第8章では、「何に対して課金されるか」でツールを比較した。たとえばLangSmithはtrace単位の課金が中心であり、本番トレースを全量流すほど請求が跳ねる。Langfuseは、トレース・観測・スコアをまとめたユニット制で、セルフホストも可能である。そのうえで、候補ツールの課金単位に自前のtrial数とトレース量を当てはめる。月額の桁を確認する手順を示した。

### 3. 第12章の失敗例集は、設計ではなく運用の失敗を集めている

評価セットの汚染、ジャッジのドリフト、ゲートの形骸化、平均スコアへの過信などである。設計が正しくても運用で壊れるパターンを、独立した章に集めた。評価の失敗は、作った直後ではなく、数ヶ月回したあとに静かに起きる。その兆候と対処を先に知っておくための章である。

## 無料連載との違い

先行して無料の連載記事を3本出している。1本目はベンチマークの読み方、2本目はLLMジャッジ校正の考え方、3本目はpass^kと信頼性である。改稿後の実態に合わせて、連載と本の線引きを対照表で示す。

|  | 無料連載で読めるもの | 本でしか得られないもの |
|---|---|---|
| 扱う範囲 | 考え方と問題提起、小さな実演1件（例：kappaが一致率の嘘を見抜く計算、pass^kの試算） | 設計の手順、計算の全過程、しきい値の決め方 |
| 成果物 | その場で使える確認表・層別表の見本 | コピーして使う雛形・校正シート・選定マトリクス（付録A〜C） |
| 対応する章 | 第1章、第6章、第5章の入口 | 第2〜12章の全体と付録。特に校正手順は第6章、ゲート設計は第7章、曲線の読み方は第9章 |
| 向いている用途 | 考え方に納得できるかの判断 | 自分のプロダクトで評価を組み立て、運用する段階 |

考え方だけ知りたい場合は連載だけで足りる。自分の評価を組み立てる段階で必要になる手順と道具が、本の側にある。
