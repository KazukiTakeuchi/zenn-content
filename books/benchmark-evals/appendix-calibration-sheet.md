第6章では、LLM-as-a-Judgeを計測器として扱うと述べた。あわせて、使う前に校正し、使い続ける間も校正し直す必要があると述べた。本付録は成果物である。校正を「始めるための道具（実行キット）」「記録するシート」「節目で開くチェックリスト」の3点セットを置く。解説は第6章に任せ、ここでは手順と数値だけを残す。

## 使い方（この順で作業する）

1. §1の手順で校正セットを抽出する（初回は200件を目安にする）。
2. §2のラベラー指示書をそのままラベラーに渡し、人間2名に独立判定させる。不一致は第6章§1の手順どおり、2名の協議で裁定する。
3. §3のジャッジプロンプト雛形に失敗クラスと判定基準を差し込み、ジャッジを実行する。
4. 結果を§4の校正シートに記録し、§5の手順で補正スコアと信頼区間を計算する。合否は§4のバイアス基準と第6章の目安で判定する。
5. 校正のたびに§6の履歴サマリ表へ1行追加する。運用の節目では§7のチェックリストを使う。

## 1. 実行キット(1)：校正セットの作り方

校正セットは「本番の分布を保ちつつ、fail側を検証できる件数まで厚くする」ことが目的である。手順は次のとおり固定する。

1. 母集団を決める。対象の失敗クラスが判定対象になる本番トラフィック（直近1か月分など）を母集団とし、評価対象の開発・調整に使った事例は除外する。
2. 無作為抽出で土台を作る。まず120件を無作為に抽出する。これが分布の土台になる。
3. 層別に上乗せする。過去に問題になった事例と境界事例（判定が割れそうな事例）を80件まで意図的に加える。合計200件を初回の目安とする。
4. 比率を整える。人間判定の結果としてpass／failがおおよそ120件／80件（6:4）程度になるようにする。failが50件を切ると、第6章の本校正の下限（各クラス50件以上）を満たさず、特異度の推定も荒くなる。無作為分だけでfailが足りない場合は、手順3の上乗せ分で補い、上乗せした件数と理由をシートに記録する。
5. 固定する。抽出した200件のID一覧を版管理し、以降の再校正でも同じセットを使う。事例を差し替えたら校正IDを新しくする。

抽出チェック（開始前に確認する）：

- [] 母集団の期間と件数が決まっている
- [] 開発・調整に使った事例が混ざっていない
- [] 無作為分と意図的上乗せ分の内訳が記録できる
- [] 人間判定後にfailが50件以上になる見込みがある（第6章の本校正の下限）
- [] バイアス検査用の事例（§4）が別枠で用意できる

## 2. 実行キット(2)：ラベラー指示書の実例

以下をコピーし、失敗クラス名と基準だけ差し替えてラベラーに渡す。

```text
対象：失敗クラス「FC-05 権限確認の省略」（付録Aの正典リスト）
あなたは評価対象の応答を読み、次の基準だけで pass / fail を判定してください。

基準: 応答または実行手順の中で、規程上必要な手順を一つでも省略していたら fail。
すべて実施されていれば pass。
対象になる手順: (1)注文情報の照会 (2)規程への適合確認 (3)金額の提示と本人の確認応答。
手順以外の観点（丁寧さ、文章の上手さ、応答の速さ）は判定に含めないでください。

進め方:
- 他のラベラーの判定は見ないでください。相談は判定後に行います。
- 判断に迷う事例は fail / pass を無理に決めず「要裁定」に印を付け、理由を1行書いてください。
- 迷った理由は基準の文面の改善材料になります。遠慮なく書いてください。
- 1件あたりの目安は3分です。全200件を2日に分けて実施してください。
```

## 3. 実行キット(3)：ジャッジプロンプトの雛形

付録A §5の変換見本と同形式である。観点は1つだけにし、出力はJSONで固定する。

```text
あなたは評価者です。以下の応答について、観点「{failure_class_name}」だけを判定してください。
他の観点は判定しないでください。

{input_context}
{reference_docs}
{response}


pass: {pass_condition}
fail: {fail_condition}

次のJSONのみを出力してください。
{"verdict": "pass" | "fail", "evidence": "判定の根拠とした箇所"}
```

## 4. ジャッジ校正シート — 校正1回につき1シートで記録する

校正1回につき1シートを作成する。ジャッジを複数持つ場合は、失敗クラスごとにシートを分ける。モデル名やプロンプトは「最新」と書かず、バージョンまで記録する。

| 項目 | 記入例 | 記入上の注意 |
|---|---|---|
| 校正ID／実施日／担当者 | CAL-2026-014／2026-11-10／評価担当 | 連番で管理し、過去シートを上書きしない |
| 対象ジャッジ（モデル名とバージョン） | 例：モデルX-2026-10版 | 提供側の表記どおりに書き、エイリアス名で済ませない |
| ジャッジプロンプトのバージョン | judge_prompt v1.3 | 本文の変更履歴と対応付ける。1文字の変更でも版を上げる |
| 対象の失敗クラス | FC-05 権限確認の省略（1クラスのみ） | 1ジャッジ＝1失敗クラス。複合判定は別シートにする |
| 評価対象のバージョン | 対象モデル／システムプロンプトの版 | 対象側が変われば校正の前提も変わるため併記する |
| 校正セットの件数と内訳 | 合計200件（人間判定でpass 120件／fail 80件） | 件数だけでなくpass／failの比率も書く。比率が偏ると一致率の解釈が変わる |
| 校正セットの出所 | 本番ログ由来120件／合成80件 | 出所が変わると分布も変わる。新規追加分は区別する |
| ラベラー構成 | 人間2名が独立判定、不一致は2名の協議で裁定（第6章§1） | 誰がどう付けたかを残す。裁定後のラベルを正解とする |
| 人間同士の一致率 | 生の一致率 92%／Cohen's kappa 0.83 | 2つをセットで書く。kappaが低い場合は基準の文面を先に直す |
| ジャッジと人間の一致率 | 86% | 裁定後の人間ラベルに対する一致率。本番投入の判断材料にする |
| 混同の内訳 | TP 106／FN 14／TN 66／FP 14 | 件数で残す。率だけだと後から再計算できない |
| 感度／特異度 | 感度 88.3%／特異度 82.5% | 感度は人間passを拾えた割合、特異度は人間failを落とせた割合 |
| バイアス検査：位置 | 順序入替50ペア、反転率 4% | 基準は下表。反転率が高い場合は提示順をランダム化する |
| バイアス検査：冗長性 | 同内容の長短ペア30組、長文側への偏り 2組 | 基準は下表 |
| バイアス検査：流暢さ | 文体は整っているが事実誤りを含む事例20件、検出率 85% | 誤りをpassにした件数も併記すると次回の比較がしやすい |
| 補正後の報告スコアと信頼区間 | 補正後 77.0%（95%信頼区間 71〜82%） | 算出方法は§5。ジャッジの生のpass率と補正後の値を両方残す |
| 判定 | 本番投入可 | 可／不可と、その根拠を1行で書く。一致率だけでなくバイアスとkappaも根拠に入れる |
| 次回再校正のトリガー | ジャッジ変更時／対象の大幅変更時／2027-02-10まで | 条件と期限の両方を書く。どちらか早い方で実施する |

バイアス検査の合否基準（暫定目安。自チームの実測が貯まったら見直すこと）：

| 検査 | 可 | 要対処（対処後に再検査） | 不可 |
|---|---|---|---|
| 位置：提示順を入れ替えたときの反転率 | 5%以下 | 5%超〜10%：提示順のランダム化を必須にし、再検査する | 10%超：比較形式のままでは投入しない |
| 冗長性：長文側へ判定が偏った組数（30組中） | 3組以下（10%以下） | 4〜6組：プロンプトに「長さで判断しない」旨を明記し、再検査する | 7組以上（約23%超） |
| 流暢さ：事実誤り事例の検出率（20件） | 80%以上（16件以上） | 70〜80%未満：誤りの種類を分析し、基準文面へ明記して再検査する | 70%未満（14件未満） |

記入上の原則は3つある。第一に、測っていない項目は空欄にせず「未実施」と書く。第二に、率は小数第1位まで、件数は整数で統一する。第三に、判定が「不可」だった場合もシートは破棄しない。不可の記録があることで、プロンプト修正後に何が改善したかを示せる（§6の例2がその形である）。

人間との一致率75〜90%という数字は、第6章で紹介したLabel Studioガイドの外部目安であり、本書自身の投入基準ではない。本書の主基準は第6章§2のとおりkappaとfail側一致率である。ただし下限を満たせば自動的に可とするものではない。次の場合は、一致率が範囲内でも投入を見送る。kappaが低い場合、バイアス基準で「不可」がある場合、感度と特異度の偏りが大きい場合である。逆に安全性に関わる判定では90%を超えても不足と判断することがある。

## 5. 補正スコアと信頼区間の算出方法

手順は固定である。§6の数値で検算できる。

1. 観測pass率を出す。本番N件に対するジャッジのpass率を `p_obs` とする。
2. Rogan–Gladen補正を行う。感度をSe、特異度をSpとして、補正後スコアは `(p_obs + Sp − 1) / (Se + Sp − 1)`。
3. 信頼区間は、まず `p_obs` の95%信頼区間をWilson区間で出す（本番のpass件数とNから計算する）。
4. Wilson区間の下限と上限を、それぞれ手順2の式に代入する。変換後の下限〜上限が、補正後スコアの95%信頼区間になる。この方法は感度・特異度を校正値で固定する簡易法である。校正件数が少ない（100件未満）場合は区間が実際より狭く出るので、その旨を報告に添えるか、ブートストラップで感度・特異度のばらつきまで含めて計算し直す。

検算（§6 例1の数値）：本番500件、ジャッジpass率72.0%（360／500件）。Se＝106／120＝88.3%、Sp＝66／80＝82.5%。

- 補正後スコア ＝ (0.720 ＋ 0.825 − 1) / (0.883 ＋ 0.825 − 1) ＝ 0.545 / 0.708 ＝ 77.0%
- `p_obs` のWilson区間（360／500、95%）＝ 67.9% 〜 75.8%
- 下限の変換 ＝ (0.679 ＋ 0.825 − 1) / 0.708 ＝ 71.2%、上限の変換 ＝ (0.758 ＋ 0.825 − 1) / 0.708 ＝ 82.2%
- したがって報告は「補正後 77.0%（95%信頼区間 71〜82%）」になる。

## 6. 記入例（2件）

以下は架空の数値で埋めた記入例である。実在のモデルや実測値ではない。形式と粒度の参考として使うこと。

### 例1：判定「可」の例

対象は、サポート応答エージェントの「必要な手順を一つでも省略していたらfail」という失敗クラスを判定するジャッジである。校正セットは200件で、人間2名が独立に判定し、不一致分は2名の協議で裁定した（第6章§1の手順）。

| 項目 | 記入内容 |
|---|---|
| 校正ID／実施日／担当者 | CAL-EX-001／実施日は例示のため省略／評価担当 |
| 対象ジャッジ | モデルX-2026-10版（架空） |
| ジャッジプロンプト | judge_prompt v1.3 |
| 対象の失敗クラス | FC-05 権限確認の省略 |
| 評価対象 | 応答モデルY-2026-09版／システムプロンプト v2.1 |
| 校正セット | 合計200件（人間判定 pass 120件／fail 80件）。本番ログ由来120件、合成80件 |
| 人間同士の一致率 | 生の一致率 92%（184／200件）／Cohen's kappa 0.83 |
| ジャッジと人間の一致率 | 86%（172／200件） |
| 混同の内訳 | TP 106件／FN 14件／TN 66件／FP 14件 |
| 感度／特異度 | 感度 88.3%（106／120）／特異度 82.5%（66／80） |

| 本番計測と補正 | 本番500件でジャッジのpass率 72.0%。感度・特異度で補正した報告スコア 77.0%、95%信頼区間 71〜82%（算出は§5） |
| 判定 | 本番投入可。一致率86%が目安の範囲内であり、kappa 0.83、バイアス検査はいずれも基準内であるため |
| 次回再校正のトリガー | ジャッジモデルまたはプロンプト変更時、評価対象の大幅変更時、校正セットへ新種事例を20件以上追加したとき、または3か月後の定期校正のいずれか早い方 |

例1で注目すべき点は、ジャッジの生のpass率72.0%と補正後の77.0%が異なることである。補正後の値と信頼区間を併記することで、次バージョンとの比較も区間の重なりを見て判断できる。

### 例2：判定「不可」→修正→再校正で「可」になった例

対象は、応答文の「根拠の不足」（付録AのFC-03）を見るジャッジである。1回目は落ちた。その履歴ごと残す。

| 項目 | 1回目（CAL-EX-101） | 再校正（CAL-EX-102） |
|---|---|---|
| ジャッジプロンプト | judge_prompt v0.9 | judge_prompt v1.0 |
| 校正セット | 200件（pass 118件／fail 82件） | 同一セット |
| 人間同士の一致率 | 生の一致率 78%／kappa 0.52 | 基準文面を直して再判定：生の一致率 89%／kappa 0.76 |
| ジャッジと人間の一致率 | 74% | 84% |
| 混同の内訳 | TP 92／FN 26／TN 56／FP 26 | TP 103／FN 15／TN 65／FP 17 |
| 感度／特異度 | 感度 78.0%／特異度 68.3% | 感度 87.3%／特異度 79.3% |
| バイアス検査 | 流暢さ検出率 60%（12／20件）で「不可」。位置 6%（要対処） | 流暢さ検出率 85%（17／20件）。位置は提示順ランダム化後 3% |
| 判定 | 本番投入不可 | 本番投入可 |

つまずきの中身は2つあった。第一に、人間同士のkappaが0.52と低かった。原因はジャッジではなく基準側で、「根拠がない」の範囲に「規程に書かれていない一般常識的な手順」まで含めるラベラーと含めないラベラーがいた。基準文面に「根拠とは入力コンテキストと規程の記載に限る」と明記して再判定したところ、kappaは0.76まで上がった。第二に、流暢さバイアスである。丁寧で滑らかな応答ほど、金額の根拠がなくてもpassに寄っていた。プロンプトに2点を加えた。1点目は「金額・日付は入力と規程への照合結果だけで判定し、文体は評価しない」ことである。2点目は、照合した箇所を `evidence` に書かせる出力形式（§3）である。修正はこの2点だけであり、ジャッジモデルは変えていない。再校正で動いた数値（kappa 0.52→0.76、流暢さ検出率 60%→85%）が、修正の効果の記録になる。

## 8. 運用チェックリスト — 公開前・変更時・月次保守の3つの節目

各リストの冒頭にヘッダを付け、その節目に対応するものだけを使う。項目は第6章の手順の再述ではなく、節目でしか確認しない差分に絞ってある。未済のまま次工程に進む場合は、理由と対応予定を校正シートに残す。

### (a) 新規スイート公開前

実施日：＿＿＿＿／実施者：＿＿＿＿／証跡（校正シートID・PRリンク）：＿＿＿＿

- [] 失敗クラスごとにジャッジが分かれ、1ジャッジ＝1失敗クラスになっている
- [] コードで判定できる項目がジャッジから外れ、コードチェックに寄せられている
- [] §1の手順で校正セットを作り、無作為分／上乗せ分の内訳が記録されている
- [] 人間同士の生の一致率とkappa、ジャッジとの一致率、感度、特異度が校正シートに記録されている
- [] バイアス検査3種を実施し、§4の基準で判定が付いている
- [] 報告スコアが§5の方法で補正され、信頼区間付きの形式になっている
- [] 本番投入の可否と根拠、再校正のトリガーと次回期限が判定欄に書かれている
- [] スコアの公表を止める条件（一致率の大幅低下など）が決まっている
